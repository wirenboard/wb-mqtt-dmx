# Проверка на железе

## WB 8.5.1 (T507), 2026-11-03

Контроллер `wirenboard-aehceskj`, прошивка testing `unstable.latest` (сборка 202610191318, wb8/trixie,
Debian 13), ядро 6.8.0-wb162, Python 3.13.5. Порт `/dev/ttyRS485-2`, отключён в wb-mqtt-serial.
Команда: `PYTHONPATH=. python3 bin/wb-mqtt-dmx test-port /dev/ttyRS485-2 --pattern ramp …`

| Режим | Длительность | Результат |
|---|---|---|
| 40 Гц, 512 слотов | 15 с | 600 кадров, 40,0 fps, 0 опозданий, 0 откатов на tcdrain; CPU 3,6 %, RSS 12 МБ |
| 40 Гц, 512 слотов | 60 с | 2400 кадров, 40,0 fps, 0 опозданий |
| 44 Гц, 512 слотов | 60 с | 2640 кадров, 43,0 fps, 1967 «опоздавших» — кадр 512 слотов занимает ~22,8 мс на проводе при периоде 22,7 мс: предел шины, не драйвера |
| 44 Гц, 300 слотов | 30 с | 1320 кадров, 44,0 fps, 0 опозданий |
| 30 Гц, 512 слотов | 20 с | 600 кадров, 30,0 fps, 0 опозданий |

Что подтверждено программно:

- драйвер UART принимает 250 000 бод через `TCSETS2`/`BOTHER` (обратное чтение даёт 250000);
- `TIOCGRS485`/`TIOCSRS485`, `TIOCMBIS` (RTS), `TIOCSBRK`/`TIOCCBRK`, `TIOCOUTQ`, `TIOCSERGETLSR` выполняются без ошибок;
- ожидание опустошения UART по `TIOCOUTQ` + TEMT работает, `tcdrain` ни разу не понадобился.

Что ещё **не** проверено (нужен осциллограф на клеммах A/B и декодер):

- что DE действительно удерживается через RTS и линия не «плавает» между кадрами;
- фактические длительности BREAK/MAB (ожидаем ~180–250 мкс и ~25–40 мкс из-за точности `sleep`);
- что декодер принимает кадры (шаблон `blink`).

Вывод для настроек по умолчанию: 40 Гц при 512 слотах; 44 Гц только при ≤ 300 слотах.
