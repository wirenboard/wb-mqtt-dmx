# План доведения wb-mqtt-dmx до продакшена

Черновик от 2026-11-18. Составлен по состоянию ветки `feature/prototype` и по требованиям Wiren Board
к Python-сервисам: шаблон [wb-python-service-template](https://github.com/wirenboard/wb-python-service-template),
[codestyle](https://github.com/wirenboard/codestyle), правила сборки пакетов в Jenkins. Решения, помеченные
«решить», ждут ответа владельца проекта; спрашиваем по одному.

## 0. Принятые решения (2026-11-18)

1. Объём первой версии: стартовый пакет, как в прототипе. Приём Art-Net и sACN входит. Пауза между каналами
   остаётся дополнительной настройкой. JSON-шаблоны приборов не входят.
2. Релизы: только trixie. Bullseye не поддерживаем.
3. Ревьюер пока не назначен. Собираем код в ветке `feature/dmx-v1`, коммиты идут по частям из раздела 3, чтобы их
   можно было превратить в отдельные PR.
4. Сначала собираем код, потом проверяем на железе по `docs/test_plan.md`.
5. Программист принимает перенесённый код после ревью, заново не переписывает.
6. (2026-11-19) MQTT переводим на библиотеку [wb-mqtt-python-lib](https://github.com/wirenboard/wb-mqtt-python-lib):
   она станет стандартом для сервисов Wiren Board. Библиотека асинхронная (asyncio, aiomqtt), только trixie, сейчас
   подключается сабмодулем, пакет `python3-wb-mqtt-lib` готовится (PR 2 в её репозитории, ориентир 23 ноября).
   Потоки кадров остаются потоками. Что учесть: в библиотеке нет Last Will, текстовое значение не может быть
   пустым, каждая запись своего значения уходит с подтверждением (нагрузку при потоке записей измерить на
   контроллере), тесты сервиса пойдут на настоящем mosquitto.

Следствия для первой версии: схема формы лежит в пакете готовым файлом; команды `update-schema` и приведения
старых конфигов нет, потому что старых конфигов в поле не существует; пакет не правит свой конфиг при установке.

## 1. Где мы сейчас

Прототип работает на стенде и подтвердил идею: DMX512 с портов RS-485 контроллера, приборы как
MQTT-устройства, настройка из веб-интерфейса.

| Что | Состояние |
|---|---|
| Код | 2 300 строк в `wb/mqtt_dmx` (11 модулей), 820 строк тестов, 450 строк измерительных скриптов |
| История | 56 коммитов в `feature/prototype`, в `main` только лицензия |
| Тесты | 41 проходит, 2 пропускаются без `jsonschema`; запускаются при сборке пакета |
| Сборка | Jenkins собирает `.deb` на каждый push, но lintian и проверки кода в сборке выключены |
| Линтеры WB | pylint 8,94 из 10 (218 замечаний, из них 128 — длина строки: писали под 120, норма 110); black переформатирует 17 файлов из 19; isort — правки в импортах |
| Аннотации типов | есть у всех 125 функций |
| Python 3.9 | синтаксис совместим (нужно для релизов на bullseye) |
| Железо | проверено на одном WB 8.5 (testing, trixie): осциллограф на RS-485-1 и RS-485-2, два прожектора одной модели, QLC+ по Art-Net |
| Нагрузка | 2–5 % ядра на порт при 40 Гц × 512 каналов |

Чего прототип не проверял: WB7, WB6, модули WBE2, релизы на bullseye, работу сутками, перезагрузку и обновление
прошивки, удаление пакета, больше двух портов, приборы других моделей.

## 2. Что считаем продакшеном

Пакет можно отдавать в релиз, когда выполнено всё из списка:

1. Сборка в Jenkins зелёная со включёнными проверками: `black`, `isort`, `pylint` 10,00 из 10, `lintian` с профилем WB.
2. Пакет проходит стендовый список из шаблона на каждой целевой паре «контроллер + релиз»: установка, `--version`,
   автозапуск, перезагрузка, сохранение конфига при обновлении прошивки, удаление без следов.
3. Сутки непрерывной работы без опозданий кадров сверх нормы и без роста памяти.
4. Есть README по образцу WB и страница в вики; понятно, как подключить, настроить и что делать, если не работает.
5. Код прошёл ревью программиста WB и влит в `main` через PR.

## 3. Ветки и порядок переноса

Предложение: да, отдельная ветка, и переносим не одним куском.

- `feature/prototype` остаётся как есть: площадка для опытов и справочник. В `main` она не вливается.
- Новая ветка от `main`, рабочее имя `feature/dmx-v1`. В неё код переносится частями, каждая часть сразу в
  продакшен-виде: отформатирована, проходит линтеры, с тестами и докстрингами.
- Причина дробления: в WB ориентир на PR — 250–300 изменённых строк вместе с тестами. Один PR на 3 500 строк
  никто не сможет проверить по существу.

Порядок частей (каждая — отдельный PR в `feature/dmx-v1` или сразу в `main`, решить с ревьюером):

| № | Часть | Что внутри | Примерный объём |
|---|---|---|---|
| 1 | Каркас пакета | структура по шаблону, версия из `debian/changelog`, `--version`, `Jenkinsfile` со строгими проверками, `debian/copyright`, пустой сервис | 200 |
| 2 | Порт и кадры | `dmx_port`, `sender`, команда `test-port`, их тесты | 450 + тесты |
| 3 | Конфиг и приборы | `config`, `templates` (раскладка и каналы), `ids`, `controls` | 500 + тесты |
| 4 | Сервис и MQTT | `service`: устройства, группы, запись, состояние, статус портов | 500 + тесты |
| 5 | Форма настройки | `schema`, перенос конфига под `wb_move`, приведение старых конфигов | 350 + тесты |
| 6 | Приём из сети | `netin`, Art-Net и sACN | 350 + тесты |
| 7 | Документация | README, вики, измерения | — |

Части 2–4 больше ориентира; их придётся либо резать ещё, либо согласовать с ревьюером больший размер.

## 6. Риски

- **Точность таймингов из Python.** Работает с запасом на WB8, но на WB6 и WB7 процессор слабее, и там мы ничего не мерили. Если не уложимся,
  отправку кадров придётся переносить в небольшой модуль на C. Это меняет тип пакета с «без архитектуры» на собираемый под
  каждую платформу.
- **Редактор форм.** Его поведение не описано и уже дважды удивило. На другом релизе форма может вести себя иначе.
- **Приборы.** Проверена одна модель прожектора. Жалобы на «китайский DMX» реальны, а наши средства против них
  (частота, BREAK, MAB, пауза) на проблемном приборе не испытаны.
- **Сеть.** Art-Net и sACN не имеют защиты по своей природе. Выключено по умолчанию, но это стоит явно написать в документации.
